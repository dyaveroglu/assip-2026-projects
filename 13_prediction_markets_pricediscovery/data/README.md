# Data provenance — Project 13 (Kalshi vs Polymarket price discovery)

This folder is **not published**. It is documented here so every number in
`paper/main.pdf` can be traced to a raw source and regenerated by the numbered
scripts in `code/`. All sources are **free, public APIs**; no authentication,
credentials, or paid vendor feeds are used, and nothing is hand-edited.

## Sources

- **Kalshi** — CFTC-regulated US event exchange.
  Endpoint: `https://api.elections.kalshi.com/trade-api/v2` (public candlestick
  endpoint). We pull hourly candlesticks per outcome market; the candle **close**
  is the last YES trade price in cents, which we store as a probability in `[0,1]`.
  Kalshi retains high-frequency history only for markets that are open or very
  recently resolved, which is why the FOMC sample is bounded to four meetings
  (a data-availability constraint, not a design choice).

- **Polymarket** — crypto-native, on-chain order-book exchange.
  Metadata: Gamma API `https://gamma-api.polymarket.com` (market/outcome mapping).
  Prices: CLOB `https://clob.polymarket.com/prices-history` — hourly YES-token
  price in `[0,1]`.

## Sample

Four 2026 FOMC monetary-policy meetings that **both** venues list with retrievable
hourly history as of the July-2026 data cut: June (resolved — the Fed held),
July, September, and October. Each meeting has five mutually-exclusive outcome
markets on each venue (hold / 25bp cut / 50+bp cut / 25bp hike / 50+bp hike),
matched one-to-one by outcome. Both venues resolve to the **same** published FOMC
statement, which is why FOMC decisions are the cleanest identical-settlement event.

## Folder layout

- `raw/kalshi/*.csv`, `raw/poly/*.csv` — one file per `<meeting>_<outcome>`,
  columns `ts` (Unix seconds), `price` (YES probability), and `volume` (Kalshi).
  Downloaded by `code/00_pull.py`; date-stamped in `raw/manifest.csv`; never edited.
- `interim/` — reserved for the analyst's hand-verification artifacts
  (`settlement_audit.csv`, `matched_pairs_v2.csv`); see `STUDENT_TASKS.md`.
- `processed/matched_panel.csv` — aligned hourly panel (`pair, meeting, outcome,
  ts, kalshi_p, poly_p`), produced by `code/10_build.py`.
- `processed/pairs_selected.csv` — one row per candidate pair with coverage,
  price variation, and the selection flag.

## Reproduction

```
python3 code/10_build.py        # build the aligned hourly matched panel
python3 code/20_analyze.py      # Hasbrouck / Gonzalo–Granger / lead–lag / Granger
python3 code/25_event_study.py  # June-2026 resolving-news event study
python3 code/30_figures.py      # figures 1–4
python3 code/35_tables_tex.py   # render base tables (tab_sample … tab_event)
python3 code/40_extensions.py   # extension tables + fig5 (inference/hetero/altspec/power)
```

`code/00_pull.py` re-downloads the raw series from the two public APIs; it is not
required for reproduction because `raw/` is already populated.

## Reserved for the analyst (NOT constructed by the automated pipeline)

Per `STUDENT_TASKS.md`, the rule-by-rule **settlement-identity verification**, the
second hand-matched **event family**, and the **order-book liquidity** memo are the
analyst's manual contribution. The automated pipeline (including `40_extensions.py`)
uses **observable price data only** and never constructs those reserved variables.
